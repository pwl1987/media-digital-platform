# 沂蒙小戏小剧官方平台 UI/UX 视觉基线 V0.1

> 状态：**Design Freeze V0.1**。编码前所有端（小程序 / H5 / PC / App）必须对齐本基线；
> 变更必须升版本号并同步 `packages/design-system`。本基线细化
> `docs/product/OPERA_OFFICIAL_IDENTITY_BASELINE_V0.1.md` 第 5 节的首屏排序，
> 并与 `docs/ux/UX_ACCEPTANCE_GATE_V0.1.md` 的 Gate B/E/F 挂钩。

## 1. 视觉定位

**「现代中国文化门户」**，不是互联网内容 App。

对标：人民日报文化频道、国家博物馆数字展览、故宫数字平台、央视节目专题页、山东文化云。

关键词：权威 / 文化 / 品质 / 沉浸 / 传播 / 现代化。

负面清单（禁止出现的视觉倾向）：

- 花哨渐变、娱乐化、电商促销感（倒计时、抢购角标）
- 社交社区感（点赞数、评论区入口、粉丝数）
- 游戏化（勋章墙、任务、抽奖）
- SaaS 风（大圆角胶囊大按钮、彩色投影、营销 Banner 轮播）

官方气质三要素（首屏必须可感知）：官方徽章、来源信息、专题策划入口。

### 2.3 状态语义映射（与领域字段一一对应）

| 字段 | 取值 | 视觉 |
| --- | --- | --- |
| `Content.status` | `published` | 正常展示，不加状态标 |
| `Content.status` | 草稿/审核（后台） | 前台不出现 |
| `Event.lifecycleStatus` | `upcoming` | 金色 tag「预告」 |
| `Event.lifecycleStatus` | `ongoing` | 红底白字 tag「进行中」 |
| `Event.lifecycleStatus` | `ended` | 灰 tag「已结束」 |

| `MediaAsset.liveStatus` | `upcoming` | 金色「预告」 |
| `MediaAsset.liveStatus` | `live` | 红点脉冲 + 「直播中」（红底白字） |
| `MediaAsset.liveStatus` | `ended` / `offline` | 灰「回放」/「已下线」 |

**双通道规则（Gate F）**：所有状态必须"颜色 + 文字"同时表达，禁止仅靠颜色区分。

### 2.4 使用比例与对比度

- 红：金：宣纸 ≈ 10 : 5 : 85。红色是印章式的点睛，不做大面积底色（主视觉遮罩除外）。
- 正文对比度 ≥ 4.5:1（`#3D3D3D` on `#F7F3EA` 达标）；红底白字仅限徽章、主按钮、直播标。
- PC 大屏展示时红色可适度加深至 `red-900` 渐变，保证投影环境可读。

## 3. 字体排印

- 标题栈（文化气质）：`"Noto Serif SC", "Source Han Serif SC", "Songti SC", "STSong", "SimSun", serif`
  ——用于平台名、分区标题、新闻标题、剧目名、专题横幅。小程序不内置字体文件，走系统回退。
- 正文栈：`"PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", system-ui, sans-serif`
- 数字/时间（等宽对齐）：`font-variant-numeric: tabular-nums`，时间与时长必须对齐。

| 级别 | 小程序 | Web | 用途 |
| --- | --- | --- | --- |
| display | 56rpx | 28px | 主视觉平台名 |
| h1 | 40rpx | 20px | 头条标题、详情页标题 |
| h2 | 34rpx | 17px | 分区标题 |
| h3 | 30rpx | 15px | 卡片标题 |
| body | 28rpx | 14px | 正文 |
| caption | 24rpx | 12px | 来源、时间、辅助 |
| micro | 22rpx | 11px | 徽章、tag |

行高：标题 1.3 / 正文 1.6 / 长文 1.75。字重：serif 标题 700，sans 标题 600，正文 400。
剧目名一律加书名号并使用 serif：《沂蒙山小调》。

## 4. 布局与形状

- 间距基数 8（rpx 阶梯：16 / 24 / 32 / 48 / 64 / 96）；页边距 32rpx；分区之间留白 48rpx。
- 圆角阶梯：4rpx（tag、徽章）、8rpx（按钮）、12rpx（卡片、横幅）。克制，不做大圆角。
- 阴影仅两级：静置 `0 2rpx 12rpx rgba(31,31,31,0.06)`；悬停/浮层 `0 8rpx 24rpx rgba(31,31,31,0.10)`。禁止彩色投影。
- 分割线 1rpx `--ym-line`。
- PC：内容容器 max-width 1200px，12 列栅格，gutter 24px。

## 5. 官方感组件

### 5.1 OfficialBadge 官方徽章（核心信任组件）

映射 `sourceLevel`：

| sourceLevel | 徽章 | 样式 |
| --- | --- | --- |
| `official` | 官方发布 | 红底白字 micro |
| 官方专题 | 官方专题 | 金底白字（`gold-500`） |
| 媒体转载（P1） | 媒体报道 | 灰描边灰字 |

出现在：新闻卡左上角、新闻详情标题上方、专题横幅角标。

### 5.2 SourceMeta 来源信息行

`来源：{sourceName} · {date}(ISO 转中文)`，caption 灰。新闻卡、头条大卡、详情页必带（Gate B：来源可被用户理解）。

### 5.3 SectionHeader 分区标题

左 6rpx×32rpx 沂蒙红竖条 + h2 标题 + 右侧红色文字链「更多 →」。

### 5.4 TopicBanner 专题横幅

宣纸白或红金渐变底 + serif 专题名 + 金色装饰线 + 「进入专题」。首期专题：沂蒙戏曲传承 / 精品剧目展播 / 文化惠民演出。

### 5.5 OfficialFooter 官方页脚

主管单位、承办单位、备案号、版权声明。所有端页脚必带——领导审查场景的"机构感"来源。

## 6. 内容组件

### 6.1 NewsHeadlineCard 头条大卡

图 16:9 + OfficialBadge + h1 标题（≤2 行）+ 摘要（≤2 行）+ SourceMeta。底部 2rpx 金色细节线。

### 6.2 NewsCard 新闻列表卡

左文右图（图 216×144rpx）或纯文字：h3 标题（≤2 行）+ 摘要 1 行 + SourceMeta。

### 6.3 ContentCard 剧目/展演卡

海报 3:4 + 标题 + 副信息（剧种 / 时间 / 地点）+ tag（荣誉金色、剧种灰描边）。展演卡右上角 lifecycleStatus 徽标。

### 6.4 MediaCard 视频卡（电视台属性核心组件）

**必备字段**：封面（16:9，底部 8% 墨黑渐变保证角标可读）、右下时长角标（tabular 数字 `mm:ss`）、标题 ≤2 行、来源 caption、清晰度 tag（1080P）、分类 tag（专题片 / 幕后花絮 / 演出实录）。

> 数据缺口：当前 `packages/mock-data/opera.js` 的 MediaAsset 仅有 `title/category/status`，
> 缺 `cover / durationSeconds / resolution / sourceName`。实现阶段按此规范补齐（对应 Sprint 任务 2）。

### 6.5 其余

- Tag：高 36rpx、micro 字。灰描边（分类）/ 金底（荣誉、预告）/ 红底白字（进行中、直播）。
- Button：主＝红底白字；次＝白底红字红描边；文字按钮红字。禁用灰。
- Empty / Loading / Error / Offline：宣纸底 + 线稿图形 + caption 文案；异步页六态齐备（Gate C）。

## 7. 首页规范（小程序）

分区顺序（本基线冻结，细化身份基线 §5）：

```
主视觉      平台名(serif) + "官方数字传播平台" + 主视觉海报/视频 + 红金渐变遮罩
最新动态    权重 ≥60%：头条大卡 + 新闻列表 ×3~5 + 更多        ★★★★★
精品剧目    海报卡横滑（1 屏 2.2 张）
精彩影像    视频墙 2 列 × 2 行
展演活动    列表卡 ×3 + 更多
文化专题    TopicBanner 横滑（1 屏 1.2 张）
官方页脚    主管单位 / 备案 / 版权
```

tabBar（与 app.json 一致）：首页 / 资讯 / 剧目 / 视频 / 我的。

## 8. 新闻详情规范（传播闭环）

```
官方发布徽章
标题 h1
摘要引言块（red-100 底 + 左 6rpx 红条）
SourceMeta：来源 · 发布时间
────────────
正文（长文 1.75 行距，图文混排）
────────────
相关剧目   横滑 ContentCard
精彩视频   横滑 MediaCard
推荐阅读   NewsCard ×3
────────────
分享（微信转发卡片：标题 + 封面 + 来源）
```

## 9. 剧目详情规范（文化档案，不是商品页）

```
剧目海报（3:4 居中或全宽）
《剧名》 serif h1
剧种 · 创作年代 · 主演
────────────
剧情简介
精彩片段（MediaCard）
主创团队（人物行卡）
演出记录（时间线）
相关新闻 / 相关专题
```

禁止出现：购买、收藏、点赞、打赏、会员等任何电商/社交元素。

## 10. 视频与直播

- 视频墙：小程序 2 列、PC 3~4 列；顶部分类 tab（全部 / 专题片 / 幕后花絮 / 演出实录）。
- 直播卡：liveStatus 视觉见 §2.3；`live` 红点脉冲 + 「直播中」文字。
- 播放器状态齐备（Gate E）：首帧封面 / 缓冲 / 播放失败 / 无播放地址，均有明确文案与重试。

## 11. 分端适配

- **小程序**：rpx 体系。导航栏与 tabBar 选中色统一 `--ym-red-700 #8B1E24`
  （现 app.json 为 `#7A1F1F`，实现本基线时同步修改）。
- **H5（分享落地页）**：3 秒原则——首屏直出 标题 + 主图/视频 + 摘要 + 官方徽章 + 来源，
  无复杂导航；底部「进入官方平台」入口。
- **PC 官方门户**：第一屏 60–70vh 文化大片 Banner（舞台影像视频背景 + 墨黑向下渐变 + serif 平台名 + 金线）；
  第二屏新闻中心（头条大卡 2:1 + 右侧列表）；第三屏精品剧目 4 列；第四屏专题；页脚官方信息栏。
  hover 上浮 2px + 阴影升级。

## 12. Token 落地约定

`packages/design-system` 为唯一 token 来源：`tokens.json`（源）→ 生成 `tokens.wxss`（小程序）与 `tokens.css`（Web）。
命名即本文 token 名（`--ym-*`）。各端可换肤但不得绕过 token 直写色值。

实现顺序：tokens → 官方感组件（§5）→ 内容卡（§6）→ 首页（§7）→ 详情页（§8/§9）→ 视频墙（§10）。
