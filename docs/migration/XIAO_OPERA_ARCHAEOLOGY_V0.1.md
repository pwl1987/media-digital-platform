# 小戏小剧旧小程序考古结论 V0.1

来源仓库：`pwl1987/xiao-opera-miniapp`

## 结论

旧项目可作为迁移来源，但不直接作为新产品基线。

### 可复用资产

- 原生微信小程序工程经验与页面组织方式
- 剧目列表 / 剧目详情
- 直播详情
- 活动页面
- 自定义 TabBar
- 音频播放器组件
- 分享、收藏、播放历史相关能力

### 必须重新设计

- 产品导航：旧版采用“首页 / 视听 / AI创作 / 活动 / 我的”，新产品改为围绕“剧目 / 展演 / 直播 / 演员 / 剧团”的内容消费模型。
- 数据层：旧版存在本地数据管理器与 AI service；新版本必须通过统一 API Client 对接外部 API，页面禁止直接依赖本地业务数据。
- 内容模型：剧目、演员、剧团、演出、活动、媒体必须成为独立领域对象，并允许相互关联。
- AI 创作：不是当前小戏小剧 MVP 的核心能力，暂不作为一级导航。
- 视觉体系：旧版红色导航和“视听中心”定位不再直接继承。

## 现有证据

旧仓库的 `app.json` 包含首页、个人中心、日志、视听、剧目详情、直播详情、AI 创作、活动等页面，并使用 5 项 TabBar：首页、视听、AI创作、活动、我的。

这些内容证明其具备可复用的原型资产，但不足以证明全部功能已经形成生产级后端闭环，因此本仓库只复用已经验证或容易隔离的前端能力。

## 迁移原则

1. 先复制/提取 UI 与组件，再接入统一 API。
2. 不复制旧数据模型作为新 canonical model。
3. 不把旧项目的 Mock、本地存储或静态数据当成生产事实来源。
4. 新项目以 `media-digital-architecture` 的领域对象和 API Contract 为约束。
