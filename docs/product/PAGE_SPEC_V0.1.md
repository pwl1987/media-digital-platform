# 页面规格 V0.1

> 本文是进入 UI 批量实现前的产品门禁。页面先定义职责、状态与数据，再实现视觉。

## 一、共享页面规则

每个列表页必须定义：首次加载、下拉刷新、分页/继续加载、空状态、网络错误、内容下架/不可用。

每个详情页必须定义：主内容、关键元数据、主操作、关联内容 `relations`、分享、收藏、不使用时的不可用状态。

所有媒体内容必须定义：封面、媒体类型、播放/预览状态、加载失败、权限/失效提示。

## 二、沂蒙精神智能平台

### Tab 1：首页

目的：3 秒内说明平台价值，并提供 AI、知识、展馆三个主入口。

模块顺序：品牌/搜索入口 → AI 智能助手 → 精选内容 → 人物/故事/历史/地点快捷入口 → 主题展馆 → 最新/推荐内容。

### Tab 2：知识

一级分类：人物、故事、历史、地点、文献、专题。列表项进入实体详情；详情优先结构化信息，再展示媒体与相关内容。

### Tab 3：AI 问答

必须支持：新建会话、多轮对话、生成中、停止生成、重新生成、复制答案、来源/证据卡片、相关内容、会话历史、不支持问题的降级提示。

AI 不是孤立功能。人物、故事、地点、内容详情页都可以通过“问问 AI”把当前对象作为上下文进入会话。

### Tab 4：展馆

采用专题/沉浸式内容页，不依赖真实 3D。类型：主题展、人物馆、故事馆、影像馆。

### Tab 5：我的

仅保留：收藏、浏览历史、会话历史、设置/协议。

## 三、沂蒙小戏小剧展演平台

### Tab 1：首页

模块顺序：搜索 → 主视觉/重点展演 → 精品剧目 → 正在直播/直播预告 → 近期展演 → 演员/剧团 → 专题内容。

### Tab 2：剧目

分类：全部、传统戏曲、现代小戏、红色题材、地方戏、精品剧目。

剧目详情：海报/主视频、剧目简介、主创、演员、剧团、演出记录、相关视频/图集、相关活动、收藏/分享。

### Tab 3：展演

分为：即将开始、进行中、历史回顾。活动详情：活动介绍、主办/承办、时间/地点、演出场次、节目单、报名入口（如有）、活动图片/视频、活动回顾。

### Tab 4：直播

状态：直播中、即将直播、已结束。直播详情必须区分直播源故障、尚未开始和已结束。

### Tab 5：我的

仅保留：收藏、观看历史、活动报名、设置/协议。

## 四、跨内容导航

任何详情页都允许继续进入关系目标：人物 → 故事/文章/视频/地点；故事 → 人物/地点/文献/视频；剧目 → 演员/剧团/演出/视频；演出 → 剧目/演员/地点/活动；活动 → 演出/直播/回顾。

## 五、微信体验要求

首屏避免重度网络依赖；弱网保留已加载内容；图片统一懒加载；视频仅在用户明确进入播放场景后建立播放资源；分享可直接落到详情页；登录不是首屏硬门槛；收藏/历史允许游客本地保存，登录后再同步。
