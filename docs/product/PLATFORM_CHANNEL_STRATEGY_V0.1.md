# Media Digital Platform — Channel Strategy V0.1

## 定位

统一内容平台，多渠道呈现。内容、资产、关联关系与发布策略属于平台事实；小程序、H5、PC Web、移动端 App 负责不同场景的体验。

## 渠道

| 渠道 | 核心定位 | 第一优先级 |
| --- | --- | --- |
| 沂蒙精神微信小程序 | AI + 知识传播 | AI问答、知识、展馆 |
| 沂蒙小戏小剧微信小程序 | 官方宣传与传播 | 资讯、剧目、视频、展演 |
| 小戏小剧 H5 | 分享传播落地页 | 新闻、剧目、活动、专题 |
| 小戏小剧 PC Web | 官方门户/内容中心 | 资讯、专题、剧目、视频、展演 |
| 沂蒙精神 PC Web | 权威知识/AI门户 | 知识、人物、故事、数字展馆、AI |
| 移动端 App | 长期沉淀的原生内容消费端 | 内容订阅、视频、AI、收藏历史 |

## App 策略

第一阶段采用单一移动 App 产品壳，通过“频道/专区”承载沂蒙精神与小戏小剧内容，而不是先维护两套原生 App 工程。这样可以共享登录、推送、播放器、收藏、搜索、下载与埋点基础能力。

App 与小程序不要求完全相同的 IA：小程序强调微信内传播，App 强调持续使用和沉淀。

## PC Web 策略

PC Web 是正式门户，不是移动页面简单放大。第一版重点：

- 官方资讯首页
- 专题策划
- 剧目/人物/机构/活动档案
- 视频与图片
- 搜索
- 内容详情
- AI/知识入口

## 共用原则

1. 所有渠道使用同一 Content / Asset / Relation 身份。
2. 发布策略由后台控制，客户端不决定内容事实。
3. 详情页 URL 可作为稳定传播入口。
4. 渠道特有能力只能放在 Experience 层。
5. 后端 API 以领域对象和 Feed 为中心，不按渠道复制。
