# 页面信息架构 V0.1

状态：Draft → Implementation Gate

## 1. 总原则

- 页面是体验层，不拥有业务事实。
- 所有业务数据经统一 API Client 获取。
- 首页是运营聚合页，不是固定内容页。
- 详情页必须支持相关内容、来源/证据、分享和异常状态。
- 一级导航只放高频任务；低频能力进入二级页面。
- 两个小程序保留不同产品气质，但共享领域语言和交互原则。

## 2. 沂蒙精神智能平台

## 4. Universal Page Templates

统一定义以下页面模板：

- HomeTemplate
- ListingTemplate
- DetailTemplate
- SearchTemplate
- SearchResultTemplate
- MediaPlayerTemplate
- EventTemplate
- EntityTemplate
- AIConversationTemplate
- TopicTemplate
- EmptyState
- ErrorState

## 5. Cross-content navigation

任何详情页至少支持：

- 相关内容
- 相关媒体
- 相关人物 / 机构 / 地点
- 返回上一级
- 分享

导航关系必须来自 Content Relation，不允许页面自行拼接字符串关系。

## 6. 页面状态标准

每个数据页面必须定义：

- loading：骨架屏 / 占位
- empty：明确原因与下一步
- error：可重试
- offline：网络不可用提示
- not-found：内容不存在或已下线
- unauthorized：需要登录时再引导
- submitting：表单提交中
- success：操作成功反馈

## 7. 适老化与可访问性

- 主要按钮点击区域充足
- 正文默认可读字号
- 颜色不得单独承担语义
- 视频默认提供字幕入口
- 核心信息避免仅依赖图标表达
- 长内容保持清晰的段落与层级

## 8. 分享

支持：
- 首页
- 内容详情
- 人物 / 剧团
- 剧目
- 活动
- 直播
- AI 会话 / 问答结果

分享参数统一由体验层生成，目标资源由 API / Content ID 决定。

## 9. 不进入 V0.1 的能力

- 私信 / 社交关系链
- 复杂积分体系
- 电商
- 礼物打赏
- 用户动态社区
- 复杂个性化推荐
- 3D 数字展馆
- AI 图像 / 视频生成

这些能力必须经过单独需求评审，不得直接扩展 MVP。
